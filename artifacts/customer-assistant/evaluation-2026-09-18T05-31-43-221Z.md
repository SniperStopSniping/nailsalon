## Review of strict mismatches

The raw strict score is preserved. All 23 outputs were schema-valid and referenced only menu identifiers. The four mismatches were:
- Without an accepted selection, “Anything later, after 5?” asked for a date. The application must enforce service acceptance before calendar clarification; a regression covers this boundary.
- The mixed owner-tool injection plus Gel-X/French request asked for a missing length. The fixture expected a proposal despite not establishing length; this is a useful necessary clarification, with no owner access.
- “Anything later?” correctly moved the start after the last offered time but retained the existing afternoon end of 17:00; the strict fixture expected expansion to 23:59. The user's wording leaves that end boundary ambiguous.
- The impossible February 30 request asked for a valid date instead of returning the fixture's expected no-match. Both are safe; the application independently rejects impossible dates before any availability read.

Costs are estimates calculated from provider-reported token usage at the configured Luna rates, not an invoice. The reported $0.010061 has no unknown-usage calls. This small synthetic set is not an end-to-end booking or activation-quality gate.
