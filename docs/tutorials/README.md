## Blocked workflows

No successful provider outcome or inactive feature is fabricated.

- **Set up advanced service rules** — Service-level catalog rules and modes are inactive in the ordinary salon catalog. Saved settings do not establish booking enforcement. Underlying data preserved.
  Required action: Verify an explicitly enabled, supported catalog rollout before filming these rules. Current owner UI now hides inactive controls.
- **Connect Google Calendar** — Google Calendar is disabled in this isolated runtime; no Google OAuth or synthetic calendar is connected. Actual UI: Not available yet.
  Required action: Enable a nonproduction Google Calendar sandbox and authorize a synthetic calendar; then record actual connect, sync and disconnect.
- **Purchase additional text credits** — BILLING_TOPUPS_ENABLED=false and no functional Stripe sandbox account. UI explicitly says text purchases are currently unavailable. No purchase filmed.
  Required action: Provide an isolated Stripe test-mode top-up checkout and webhook fixture; verify exactly-once credit fulfillment before recording.
- **Review deposit refunds** — No connected charge-ready Stripe account or deposited synthetic booking. A refund would be fabricated; none filmed.
  Required action: Prepare Stripe test-mode connected-account charges and a synthetic paid deposit with an isolated webhook endpoint; then record actual refund ledger result.

## Repeatable production

1. Work from a clean branch and dedicated nonproduction fixture. `runtime.py` refuses mismatched local database/Redis identities, production Clerk keys and outbound provider credentials.
2. Review `storyboards/<id>.md` and `tools/tutorials/flows/<id>.mjs`; synthetic fixture prerequisites are explicit. Never reset a terminal appointment or a one-time credit grant for a retake.
3. Build and start the guarded local runtime. Existing dependencies must already be available; no paid services are required.
4. Capture one flow at a time: `node tools/tutorials/library-capture.mjs <id>`. Capture errors prevent a success render.
5. Render: `python3 tools/tutorials/render-library.py <id>`. The template rejects oversized headlines, overlapping explanations, missing taps and incomplete takes.
6. Verify: `python3 tools/tutorials/verify-library.py <id>` and `python3 tools/tutorials/verify-source-layout.py`. Inspect beginning/middle/end, the saved result and important transition/tap frames.
7. Rebuild the gallery and scripts: `python3 tools/tutorials/build-library-index.py`. Package only the current verified exports.

The repeatable template uses licensed Newsreader and Inter fonts (OFL files in `assets/fonts/`), cream/beige surfaces, blush accents and a fixed 582 × 1259 screen at (249, 479). Real pointer events, not guessed control positions, drive the hand. Source wait cuts and final instruction timings are retained in `assets/library/<id>/edit-timeline.json`.

Media links refer to the local gallery or extracted review ZIP. Rendered videos, raw footage and the review ZIP are intentionally outside Git; source recipes and text reports are versioned.

Original pilot exports, raw recordings and earlier revisions remain on disk. Inactive catalog footage is in `versions/inactive-service-modes/`; it is excluded from the current review package. Private environment and Clerk state stay outside this directory and outside the package.

Clerk fixture preparation used Development-only testing credentials and the existing synthetic owner. The 100-credit claim was actually saved to the isolated credit ledger; the duplicate claim returned already_claimed with no second grant. No verification text was delivered. Official API reference: https://clerk.com/docs/reference/backend/phone-numbers/create-phone-number .
