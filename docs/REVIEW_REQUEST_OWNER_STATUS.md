# Owner review-request status and history

The appointment card projects durable trigger/request/intent/provider evidence without changing review admission or delivery. Before a trigger exists it says the automation is waiting; a recorded trigger or intent can show Scheduled. Quiet hours are reflected in a pending trigger's displayed time. Cancellation, no-show, suppression, recipient changes, expired windows, missing configuration, and conflicting client history explain why unsent work will not qualify.

A previous visit's send is never shown as this appointment's send. Provider acceptance is Sent; only a delivered provider record supports Delivered. Owner-marked native-device sends remain explicitly unverified. Unknown outcomes block manual actions rather than being retried through a new request. Accepted history remains visible after later appointment changes.

Manual admission stays server-authoritative. An appointment action still requires the existing completion eligibility rules. Send now queues at most one applicable request; quiet hours and final dispatch checks still apply. A client-profile Google-review preset uses the coordinated client-only manual path from the preceding slice. No AI-specific producer or send path is added.

Client profiles show up to 20 recent records, source/channel, salon-local times, and suppression controls. History projections batch appointments/delivery evidence, while eligibility considers all matched client/recipient history. An old cancelled request does not hide a fresh reschedule trigger. Failed or stale loads cannot enable sending or suppression edits. Cancellation/no-show appointment sheets continue showing review history.

The settings shortcut points to Marketing & Messages → Reviews. Compatibility aliases are supplied by the owner IA stack. Existing SMS delivery remains the only automated review channel; this UI adds no email fallback or delivery guarantee.

A request stopped before sending remains Cancelled in history, while its appointment can offer a new manual request when current eligibility and matched history permit it. The confirmation previews the current client and message, not the cancelled snapshot. An active replacement takes precedence over cancelled history even when timestamps match. Unknown, failed, suppressed, or otherwise blocked outcomes do not gain a new retry action.
