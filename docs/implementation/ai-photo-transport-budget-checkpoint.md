# Website photo transport budget — 2026-10-18

New AI-builder photos and logos are prepared to at most 300 KB each, leaving room for six images within the existing 2 MB website-media envelope. Photos use the established aspect-preserving WebP pipeline with additional bounded fallbacks when needed. Logos try lossless artwork encoding first and retain alpha. Existing uploads/artifacts are immutable and are not rewritten. Canva reference/artwork handling keeps its separate profile; the manual native-resolution save fix is unchanged.

Previously, the normal photo encoder could save an image over 750 KB, only for the AI upload layer to reject and delete it. Both local private storage and the isolated Preview byte-storage path now pass the actual output bound into the encoder before saving. Complex photographs can reduce in resolution; there is no crop, stretch or invented detail. The realistic website photographs from the earlier owner trials already fit this bound. Random-noise integration fixtures verify the harder compression path, including its aspect ratio and minimum supported dimensions.

The existing aggregate-media guard is now shared by saved-artifact validation and generation preflight. Oversized historical selections fail before provider token counting, reservation or design generation. Owners are told to deselect an image or upload smaller exports; their earlier design remains intact. This avoids paying to generate a design that cannot be saved. It does not imply that an earlier conversational intake call was free.
